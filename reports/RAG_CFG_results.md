## 1. 설정

- 모델: Phi-3.5-vision-instruct 4.2B + Phi-3.5V-Med LoRA를 이어서 학습한 어댑터. VQA-RAD `checkpoint-257` (epoch 6, 10 epoch 학습 중 val 선택), SLAKE `checkpoint-380` (5 epoch).
- 평가 대상: VQA-RAD test 451 (open 179 / closed 272), SLAKE 영어 test 1,061 (open 645 / closed 416).
- **5% 게이팅**: 베이스라인 생성의 평균 토큰 엔트로피 상위 5% 문항(VQA-RAD 23, SLAKE 53)에만 Expert 처리를 하고 나머지는 베이스라인 예측을 유지한다.

- CFG: γ=1.3 (논문 Table 7에서 {1, 1.3, 1.5} 중 최고, 본문 기본은 1.5), 하이라이트 attention 가중 α=0.01 / β=3.
- 채점: **공식 = 원본(Phi 3.5V 방식)**. S1+S2(open만 표기 차이 허용)는 Phi의 VQA-RAD test 오답에서 만든 규칙이라 규칙 완화이므로 참고 열로만 둔다. 아래 표의 신뢰구간은 S1+S2 기준으로 구한 것이라 원본 기준 구간은 노트북(02)을 다시 돌려야 나온다. 신뢰구간은 문항 쌍 부트스트랩 10,000회(test 표본 변동만 반영).
- 검색 지식베이스(KB): `peir` = PEIR 캡션 33,572. `peir,roco,trainqa` = PEIR + ROCO(공개본 train 캡션 65,423) + VQA-RAD · SLAKE train QA("질문 정답" 텍스트). 검색은 BioMedCLIP 이미지 쿼리 × KB 텍스트, 코사인 top-k (정확 검색, FAISS 없이 동일 결과).

## 4. 진단과 해석

**하이라이트가 실제로 작동했는가 (VQA-RAD 선택 23문항)**

| 하이라이트 | 마스크된 토큰 | 0개인 문항 |
|---|---|---|
| PEIR 키워드 (KB=`peir`) | 평균 46.4, 최대 169 | 0/23 |
| 정답 단어 (하이라이트만) | 평균 15.9, 최대 169 | 16/23 |
| 질문·캡션 공유 단어 (KB=`peir,roco,trainqa`) | 평균 1.8, 최대 6 | 9/23 |

- 선택된 open 20문항 중 **정답이 검색된 캡션·질문에 그대로 있는 문항은 0개**였다. 그래서 "하이라이트=정답" 행은 효과가 없어 결과표에서 뺐다.
- 5% 선택 문항 23개 중 21개(0.913)가 베이스라인 오답이다. 게이팅 자체는 잘 작동한다(불확실성 AUC 0.846, `Phi35V_results.md`). 그러나 정답 정보가 없으면 그 문항들을 고칠 근거가 컨텍스트에 없다. 상한은 23문항을 다 고쳐도 +5.1%p다.

**정답 주입 행이 의미하는 것.** 논문은 open 문항에서 정답을 전문가 어노테이션으로 쓰고 전문가가 참조 텍스트를 수정한다고 설명한다. 우리 주입 행(open 캡션 뒤에 `Expert note: {정답}.`)은 그 모사이고, 논문 규모의 개선(VQA-RAD +2.2~+2.5)이 이 행에서만 나온다. 팀원 구현도 open 하이라이트를 정답으로 두고 정답이 캡션에 없으면 캡션 뒤에 덧붙인다(5절). 다만 주입 형식은 우리가 정한 것이라 논문과 같다고 확인하지는 못했다. SLAKE는 주입해도 +1.0에 그쳐 논문 CFG +2.55에 못 미친다. 이유는 모른다.

**w/ RAG가 VQA-RAD에서만 크게 나빠진다.** KB를 PEIR만에서 ROCO · train QA까지 키워도 −4.46 → −4.83으로 달라지지 않았다(오차 범위). KB 구성이 원인이라는 가설은 이 실험으로 뒷받침되지 않는다. 남은 후보는 어댑터가 캡션 없는 프롬프트로 파인튜닝되어 캡션이 들어가면 open 답이 흐려지는 것이다(open 67.99 → 59.72). 검증하지 않았다.

**검색 자체는 쓸 만하다.** 검색된 top-1 캡션이 이미지의 장기를 언급하는 비율: VQA-RAD 96.5% (무작위 42.8%), SLAKE 71.1% (무작위 34.3%, 장기 단어 목록이 불완전해 하한).

**누수.** train QA를 KB에 넣었을 때 top-1이 같은 이미지의 train QA인 경우는 선택 23문항 중 1개였다. 우리 검색은 이미지→텍스트라 같은 이미지가 정확히 잡히지 않는다. VQA-RAD는 test 이미지 189/203개가 train과 겹치므로 이미지→이미지 검색을 쓰면 상황이 크게 달라질 수 있다(5절).

## 5. 다른 구현(`each-yi/phi3_urp`)과 맞춰 볼 때 확인할 항목

팀원 레포는 Phi-3-Vision(3.5 미지원)만 다루므로 점수는 비교할 수 없고 **방법**만 비교한다. 아래는 그 레포의 `generation.py` · `retrieval.py` · `evaluate.py` · `train.py`를 읽은 요약이며, 실행하거나 전체 원문을 확인한 것은 아니다.

| 항목 | 팀원 | 이 레포 |
|---|---|---|
| CFG 가이던스 식 | `γ·logp0 − (γ−1)·logp1` (log 공간) | 같은 식 (argmax 동일) |
| γ 기본값 | 1.5 | 1.3 |
| **조건부 가지** | 하이라이트 key attention에 `log β` (β=3) | CFG 행에서는 수정 없음 |
| **무조건부 가지** | 하이라이트 임베딩 ×α(0.01) **그리고** attention `−δ` (δ = log β + 2 ≈ 3.10) | attention 가중만 (하이라이트 ×0.01, 나머지 ×3) |
| 하이라이트 토큰 찾기 | 문자 오프셋 ↔ 프로세서 토큰, 불일치 시 assert | 프로세서의 대소문자 구분 문자열 매칭 |
| KB | 해당 데이터셋 train QA (이미지별로 묶음, `no` 답 제외) + 선택적 ROCO · PEIR | PEIR (+선택: ROCO 캡션, train QA) |
| 검색 쿼리 | 이미지 / 텍스트 / 합 / 합집합(max, 기본), **KB 이미지와의 유사도 포함** | 이미지 → 텍스트 캡션만 |
| top-k / 참조 | 3 / top-1 | 5 / top-1 |
| open 하이라이트 | 정답, 캡션에 없으면 캡션 뒤에 덧붙임 | 기본은 PEIR 키워드(정답 미사용). 정답 주입 행이 팀원 방식과 같음 |
| closed 하이라이트 | 질문과 단어가 겹치는 문장 최대 2개 (선택적 GPT) | PEIR 키워드 |
| closed 채점 | **첫 yes/no 토큰**이 정답과 같으면 1 (없으면 정답 토큰 포함) | 정답 단어가 예측 단어 어디에든 있으면 1 |
| open 채점 | 토큰 recall | 토큰 recall (+S1+S2) |
| 신뢰구간 | 없음 | 부트스트랩 |
| 학습 분할 | train만, val 없음, 마지막 모델 사용 | train 학습, **val로 체크포인트 선택**, test 1회 |
| 정밀도 | fp16 기본 | bf16 |

**차이가 결과에 영향을 줄 수 있는 순서 (제안)**
1. **CFG 정의.** 팀원은 조건부 가지에 β를 주고 무조건부 가지에서 임베딩과 attention 두 곳에서 하이라이트를 지운다. 우리 CFG는 무조건부 가지의 attention만 바꾼다. 우리가 논문의 CFG 개선을 재현하지 못한 원인 후보다. 선택 문항만 돌리면 되므로(VQA-RAD 23문항) 확인 비용이 작다.
2. **검색 방식.** 이미지↔이미지 검색은 train과 test 이미지가 겹치는 VQA-RAD에서 같은 이미지의 train QA를 가져와 점수를 크게 올릴 수 있다. 논문 w/ RAG가 우리보다 덜 나빠진 이유일 수 있다. 쓴다면 규칙 완화로 표기하고 누수 비율을 같이 보고해야 한다.
3. **closed 채점.** 팀원 규칙이 더 엄격하다. 우리 방식이 closed를 얼마나 높게 주는지는 우리 예측 파일로 GPU 없이 바로 계산할 수 있다 (미확인).
4. train QA KB에서 `no` 답을 버리는 규칙(논문 부록 B)을 우리 `trainqa`에는 적용하지 않았다.

| 규칙 완화 | 정답 주입 행(정답 정보 사용), S1+S2 채점(test 오답에서 도출) |

규칙 준수 행의 RAG · Expert 개선은 확인되지 않았다. 규칙 완화 행의 숫자는 논문 비교용 상한선이며 규칙 준수 결과로 보고하지 않는다.

## 7. 한계와 미확인

- 모두 1회 실행이다. 시드 간 변동을 측정하지 않았다.
- 5% 게이팅이 바꾸는 문항이 VQA-RAD 23, SLAKE 53개뿐이라 개선폭의 신뢰구간이 넓다.
- SLAKE의 `KB='peir'` 결과와 open / closed 점수, 신뢰구간은 없다.
- 일반 Expert 행이 새 KB에서 Expert 효과를 측정하지 못한 상태다. 하이라이트가 작동하는 KB(`peir`)로 SLAKE를 돌려야 두 데이터셋을 같은 조건으로 비교할 수 있다.
- 논문 Table 1의 RAG · Expert 행은 웹 추출값이며, 논문 쿼리 구성(이미지 / 텍스트 / 합 / 합집합 중 무엇을 썼는지)은 본문에서 확인하지 못했다.
- 팀원 구현과의 비교(5절)는 웹으로 읽은 요약에 근거하며 실행해 보지 않았다.

## 9. 구현과 시도 이력 (RAG · CFG 전체 과정)

### 9-1. 구현 구조 (`02` 노트북)

- **forward만 쓰는 greedy 루프**(`generate_expert_cfg`)를 쓴다. transformers 5.x + 구버전 remote code에서 `generate()` 내부의 position_ids / cache 처리가 어긋나기 때문이다. 같은 입력 2벌(조건부 / 무조건부)을 한 배치로 넣고 `guided = γ(cond − uncond) + uncond` (log-prob)로 다음 토큰을 고른다.
- **하이라이트 가중은 attention의 4D additive mask에 `log(weight)`를 더하는 방식**이다. 이 모델 코드는 2D attention mask에서 1이 아닌 값을 전부 "가림"으로 처리해서, 데모처럼 가중치를 2D mask에 넣으면 가중이 아니라 해당 행 전체가 가려졌다(진단으로 확인). 모든 self-attention 레이어에 forward pre-hook을 달아 additive mask에 bias를 더한다(eager attention 필요). `check_mask_effect`가 (1,1)=(3,3)=0, (1,0.5) < (1,0.01) 같은 기대 동작을 점검한다.
- transformers 5.x 호환 패치: `Phi3VForCausalLM` `_attn_implementation`, `DynamicCache`(`seen_tokens`, legacy cache 변환), `GenerationMixin` 추가.
- 5% 게이팅은 `01`이 저장한 베이스라인 결과의 문항별 평균 토큰 엔트로피 상위 5%.

### 9-2. 검색 파일을 만든 과정 (시행착오)

1. **기존 Drive `test.json`**(문항별 `top_k_captions`, `highlights`)은 공통 split의 test와 451/451 일치한다(closed 272 / open 179). 그러나 만든 경위를 확인하지 못했다. 이전 Kaggle 생성 노트북의 출력은 HF 데이터셋에 이미지 이름이 없어 "피처 없음 451"로 비어 있었다.
2. **재현 시도 1 — 직접 인코딩.** BioMedCLIP으로 이미지와 PEIR 캡션 33,572개를 직접 인코딩해 만든 검색이 기존 `test.json`과 거의 맞지 않았다(top1 6.4%, top5 집합 9.3%, 하이라이트 완전일치 0.9%).
3. **재현 시도 2 — 저자 이미지 피처.** 저자 h5 피처와 직접 인코딩 피처의 코사인이 평균 0.076(최소 −0.057)이라 서로 다른 공간이다. 저자 h5 × 우리 텍스트 피처로 만든 검색은 기존 `test.json`과 0% 일치했다.
4. **재현 시도 3 — 저자 `label_features`.** `text_features.h5`의 `label_features`(16,555 × 512)의 행 ↔ 캡션 대응을 복원하지 못했다. 길이가 맞는 후보가 없었고(키 25,311, 이미지 33,572, radiology 키 3,684), 이미지 번호 대응 6가지도 모두 0% 일치였다.
5. **재현 시도 4 — 질문 텍스트 검색.** 질문만으로 검색하면 top5 겹침 0.215, 질문+정답은 0.163으로 기존 파일과 달랐다. 정답이 검색에 들어간 oracle은 아니다.
6. **결정.** 기존 `test.json`과 저자 피처에 의존하지 않고, **BioMedCLIP으로 PEIR 캡션과 이미지를 직접 인코딩하는 자체 파이프라인**(`tools/build_rag_testjson.py`)을 두 데이터셋에 같은 방식으로 적용했다. 기존 `test.json`은 평가에 쓰지 않는다. 검색이 쓸 만한지는 장기 일치율로 확인했다(VQA-RAD 96.5% vs 무작위 42.8%, SLAKE 71.1% vs 34.3%).
7. **KB 확장.** 논문 설명에 맞춰 ROCO(공개본 train 65,423)와 train QA를 더한 변형(`--kb peir,roco,trainqa`)을 추가했다.

## 10. 의사결정 기록

- **공식 채점은 원본(Phi 3.5V 방식)이다.** S1+S2는 Phi의 VQA-RAD test 오답에서 만든 규칙이라 규칙 완화이므로 참고 열로만 두고 규칙 도출 출처를 명시한다. (한때 S1+S2를 공식으로 두었으나 번복했다.)
- **일반 oracle 행(하이라이트=정답)을 뺐다.** 정답이 캡션에 없어 효과가 없다. 정답 주입 행만 규칙 완화 상한선으로 남긴다.
- **KB 확장 탐색은 여기서 멈춘다.** ROCO와 train QA를 넣어도 w/ RAG가 나아지지 않았고, ROCO가 top-1을 독점하면 하이라이트 효과가 사라진다. 다만 SLAKE `KB='peir'`로 같은 조건을 맞춘 결과가 없다.
- **SLAKE 전 문항 w/ RAG는 보류한다.** 1,061문항이라 약 71분(약 2.3 unit)이고 VQA-RAD에서 RAG가 일관되게 나빴다.
